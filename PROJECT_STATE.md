### 2026-09-30 — Global Catalog API Sync + Jobs (manual run, no migration)
- **Status:** implemented in the existing development codebase without adding a database migration.
- **Scope:** API-only source sync using the existing `catalog_sources.configuration.api` contract, the same SSRF protections as `catalogSourceTestConnection`, and the current resolver / preview / commit pipeline.
- **New service:** `server/services/catalogApiSync.ts` — validates the source, resolves the credential name from `process.env`, fetches the source with a capped timeout, blocks private/internal targets before the request, resolves the saved mapping, previews the rows, then reuses the existing commit path so the sync does not invent a second matching or import engine.

- **History:** in-memory sync history exposed via `listCatalogApiSyncRuns` and `getCatalogApiSyncRunSummary`; only summary counts, timestamps, status, and sanitized messages are stored, never raw API bodies or secrets.
- **Safety:** no direct price/currency/availability writes, no global product deletion when an API row disappears, no match-by-name-only behavior, no raw payload storage, and no secret leakage to logs or history.
- **Evidence:** `tests/catalogApiSync.test.ts` covers valid config, missing credential, unsafe private URL, timeout, invalid response, resolver errors, concurrent runs, and success/failure flows using fake fetch.
